# ============================================================================
# 152-ФЗ техническая часть — памятка для SkyLine 2026
# ----------------------------------------------------------------------------
# Ст. 19: оператор обязан обеспечивать безопасность ПДн при обработке.
# Что реализовано в /api/lead.php и конфигах:
# ============================================================================

1. ЛОГИРОВАНИЕ ДОСТУПА К ПДн (ст. 19, ч. 1)
   -----------------------------------------
   • /lead-data/access.log — все события (csrf_issued, lead_created,
     rate_limited, db_error) с timestamp ISO 8601, IP-хешем, User-Agent.
   • IP хранится ТОЛЬКО как SHA-256(salt + ip + month) — псевдонимизация.
   • Оригинальный IP НЕ пишется в логи. Только в БД (если есть) с шифрованием.

2. ШИФРОВАНИЕ AT-REST (если используется БД)
   -----------------------------------------
   • Поле name_enc / phone_enc — AES-256-GCM (libsodium).
   • Ключ db_encryption_key — 32 байта base64, хранится в .env / вне webroot.
   • Nonce для каждого сообщения — отдельная колонка *_nonce.
   • Рекомендация: ключи хранить в KMS (Yandex KMS / HashiCorp Vault).

3. СРОК ХРАНЕНИЯ И УНИЧТОЖЕНИЕ (ст. 21)
   -----------------------------------------
   • pdn_retention_days = 1095 (3 года — срок исковой давности по ГК РФ).
   • В БД — колонка expires_at = NOW() + 3 года.
   • Cron-скрипт /scripts/pdn-cleanup.php — удалять строки WHERE expires_at < NOW()
     ежедневно. Запись в /lead-data/cleanup.log.
   • Логи access.log — ротация logrotate: 90 дней, затем удаление.

4. ПСЕВДОНИМИЗАЦИЯ ПРИ ЛОГИРОВАНИИ
   -----------------------------------------
   • IP в access.log — всегда SHA-256(ip + salt + month).
   • Phone в leads.log — маска: +7 XXX XXX-XX.
   • Полный телефон — только в Telegram/email (защищённые каналы) и в БД
     (зашифрован).

5. СОГЛАСИЕ СУБЪЕКТА (ст. 9, ч. 1, п. 1)
   -----------------------------------------
   • Чекбокс consent обязателен.
   • В тексте рядом — оператор (ИП SkyLine, ИНН, адрес), цель обработки,
     срок хранения, способ отзыва.
   • Бэкенд проверяет consent !== false и иначе отдаёт 422.
   • В БД — колонка consent BOOLEAN + consent_text TEXT (копия текста на
     момент подачи — доказательство).

6. ПРАВО НА ДОСТУП / УНИЧТОЖЕНИЕ (ст. 14–17)
   -----------------------------------------
   • /privacy-policy.html — инструкция: как подать запрос на удаление.
   • Endpoint /api/pdn-request.php (заготовка) — принимает запрос с
     подтверждением номера телефона (SMS-код) и удаляет запись из БД,
     логирует в /lead-data/pdn-requests.log.

7. УВЕДОМЛЕНИЕ ОБ УТЕЧКЕ (ст. 21, ч. 3.1)
   -----------------------------------------
   • При фиксации инцидента (нетипичная активность, ошибка БД) —
     отправка уведомления на security@skyline-bashkortostan.ru.
   • В течение 72 часов — уведомление Роскомнадзора (если реальная утечка).

8. РЕГЛАМЕНТ ВНУТРЕННИЙ
   -----------------------------------------
   • Назначить ответственного за ПДн внутри ИП.
   • Согласие с работниками, имеющими доступ к /lead-data — подписать NDA.
   • Регулярный аудит прав доступа к директории (chmod 770, www-data only).
